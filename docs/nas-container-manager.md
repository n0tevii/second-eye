# 群晖 Container Manager 部署与回滚

本文对应发布 `v0.2.0`。在 NAS 型号、CPU 架构、DSM / Container Manager 版本、可用内存、卷名、端口和 HTTPS 入口核实前，部署状态为 **NOT_VALIDATED**。

## 目录与权限

先在实际数据卷上选择应用专用目录，不要照抄未核实的卷名：

```text
<实际卷>/docker/second-eye/
  compose.yml
  .env                         # 管理密码，仅 NAS 管理员可读
  releases/v0.2.0/             # 固定发布包，不含运行数据
  data/                         # SQLite、日志、浏览器 profile、Cookie 和业务密钥
  backups/<时间>-pre-v0.2.0/   # 升级前 data 与部署配置快照
```

Cookie、模型密钥和通知密钥会以明文保存在 SQLite，浏览器 profile 也含登录态；应用不提供静态加密密钥托管。`data/`、`.env` 和 `backups/` 因此都应按秘密凭据保护，只允许 NAS 管理员及容器运行身份读取，不进入 Git、镜像、公开压缩包、普通共享或云端明文同步。应用入口只经 HTTPS 反向代理访问；Compose 的宿主端口保持 `127.0.0.1` 绑定。

## 首次部署前的固定值

在 Container Manager 创建项目前核实并记录：

- NAS 型号与 CPU 架构：`待填写`
- DSM / Container Manager 版本：`待填写`
- 实际目录与卷：`待填写`
- 可用内存和计划资源上限：`待填写`
- 应用 loopback 端口：`待填写`（模板默认 18000）
- noVNC loopback 端口：`待填写`（模板默认 16080，默认无监听）
- HTTPS 域名、证书和反向代理目标：`待填写`
- 固定源码版本：`v0.2.0`，提交 SHA 在发布后填写
- 构建后的镜像 ID / digest：`实际构建后填写`
- 模型提供方、月度费用上限和通知渠道：`待填写`

复制 `.env.example` 为 `.env`，将 `ADMIN_PASSWORD` 替换为至少 16 位的唯一强密码。Cookie、模型密钥、Webhook 和 Token 由使用者直接在受保护的设置页填写，不通过聊天传递。反向代理必须保留外部 `Host`，否则同源写请求校验会拒绝表单提交。

## Container Manager 图形界面

现场执行时每轮只做少量步骤并核对结果：

1. 在 File Station 创建应用、发布、数据和备份目录；上传 `v0.2.0` 的 Git 发布包和本文件对应的 `compose.yml`、`.env`。
2. Container Manager → 项目 → 新增，选择应用目录及 Compose 文件。首次“创建并启动”前核对：仅一个 `second-eye` 容器、无 privileged、无 host network、无 Docker socket、无宿主机大目录挂载，两个端口都只绑定 `127.0.0.1`。
3. 创建 HTTPS 反向代理到应用 loopback 端口，并保留 `Host`。不得为方便访问再添加 LAN 或公网直达端口。
4. 首次登录闲鱼时，在权限受控的 `data/.novnc-password` 写入独立强密码，临时设 `ENABLE_NOVNC=1` 后仅重建本项目；为 noVNC 反向代理启用 WebSocket。完成登录后恢复 `ENABLE_NOVNC=0` 并重建本项目。

## 升级前备份

停止 `second-eye` 项目后再复制整个 `data/`，并同时保存 `.env`、Compose、旧发布 SHA、镜像 ID / digest 和反向代理配置。备份完成后核对 SQLite 文件、浏览器 profile 和部署配置都存在，再启动新版本。

本版本启动迁移会：

- 给通知记录增加事件键和尝试次数；
- 把旧的 `gone` 状态改名为 `not_seen_recently`。

旧版本不理解全部新语义。需要回滚数据库时，必须同时恢复升级前的完整 `data/` 备份；只换回旧镜像不构成可靠回滚。

## 回滚

1. 停止本项目，保留失败版本的 `data/` 副本用于排查。
2. 将 Compose 指回旧的固定镜像/发布目录，恢复与该旧版本匹配的 `.env` 和升级前 `data/` 备份。
3. 只重建 `second-eye` 项目，不删除数据卷，不使用带 `-v` 的清理，不改动 NAS 其他服务。
4. 重新核对管理鉴权、任务数、历史记录、登录态和一次只读搜索；未经再次授权不发送真实通知。

## 实际验收

以下项目必须记录现场证据；容器显示“运行中”或健康检查通过只证明进程可响应：

- 未认证访问管理页和 API 返回 401，跨站写请求返回 403。
- noVNC 关闭时入口不可连接；临时开启时 WebSocket 要求 VNC 密码，完成登录后再次关闭。
- `/healthz` 的版本、容器镜像 ID / digest 与发布记录一致。
- 人工对照至少一个真实闲鱼搜索结果的标题、价格、配置和卖家信息。
- 一个真实任务完成；重复商品不刷屏，同价重新出现会重评。
- 模拟单渠道失败后只补发失败渠道，三次失败后停止自动重试，数据库不虚报服务端接受。
- 修改间隔实际更新 scheduler；禁用任务在下一检查点停止；新商品详情得到卖家 ID 后仍会检查黑名单。
- 用户单独授权后发送一条真实通知，并由手机确认收到且链接可打开。第三方接口“已接受”不能代替手机到达证据。
- 重启和版本更新后，任务、历史、Cookie 与浏览器 profile 按设计保留。
- 备份可读取，回滚所需旧镜像、旧配置和匹配的数据快照齐全。
