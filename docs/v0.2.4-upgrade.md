# v0.2.4：需求判定与旧结果失效修复

## 行为

- 修改任务的需求文字后，立即清除该任务商品的旧需求结论、依赖需求的分析分数和“本批最优”，标记等待重新核验。再次检索到该商品时重评，即使价格未变。未再次检索到的历史商品继续显示待核验，不自动批量抓取。
- 用输入摘要记录需求、标题和描述，避免复用不对应当前输入的结论。旧数据库首次升级时将旧分析标记待核验，保留商品、描述、价格快照和通知历史。
- 已成功渠道的历史不会删除；需求变化或首次迁移后，旧失败通知标为 `superseded`，不再补发旧结论。重评本身不重发历史商品；后续新品、价格变化、重新检索到的商品仍遵循原通知规则。不会保证通知严格 exactly-once 或手机实际到达。
- 运行中若需求变化，在检查点停止本轮，丢弃未提交的旧结果。已经发出的请求无法撤回；通知返回后仍记录实际结果，后续渠道停止使用旧需求。
- 对明确写出的内存/SSD最低容量增加本地规则；本轮用户要求“内存（统一内存）至少128GB，内置SSD容量至少2TB”可直接识别。128GB+1TB 和64GB+2TB不能被AI改判为匹配。
- 规则支持明确标签容量及内存+硬盘常见写法；容量按GB/TB十进制换算。缺失、冲突、可选升级、无法归属本机的容量保持未知。此解析器不是任意自然语言/全部闲鱼商品格式的完整解析器；无受支持容量门槛的其他需求仍由模型分析。即便容量达标，其他需求仍需模型判断，商品真实性仍需人工核实。
- 模型可以明确返回 `matched: null`。方案A保留：未知可提醒，但明确标记待核验；明确不匹配不发。
- “命中列表/命中数量”改为“收录”；任务详情区分需求匹配、不匹配和未核验数量。满足分权重不变，页面说明其仅供排序、缺失项有默认分，不是配置证明或成交价估值。

## 测试与限制

本机隔离SQLite、模拟抓取/模型/通知覆盖：需求编辑持久化、同价重评、旧正面结论失效、容量矛盾、缺失信息方案A、重复商品不重复发、分析/投递期间修改需求、迁移重复执行、保留已成功通知与价格历史。原权限和浏览器表单回归同样通过。

本版本尚未在NAS部署。本地测试不能证明闲鱼风控消失、真实详情和卖家抓取成功、模型理解准确或手机收到通知。Linux镜像构建及NAS实际升级/回滚均为 NOT_VALIDATED。
